# Module 08: SQL Indexes

An index is a sorted lookup list. `EXPLAIN QUERY PLAN` shows whether SQLite reads every row (SCAN) or jumps to the answer (SEARCH). Plans are the same on every run, so the output stays reproducible.

Run: `python run_module.py 8` | Output: `outputs/Module_08_Index/output.txt` | Starts from: the shared tables, plus a generated `pupils` table

## Lessons

| Script | Topic |
|---|---|
| 00 create_sample_tables | 20,000 pupils generated by a recursive query |
| 01 indexes | SCAN without an index, SEARCH on the primary key |
| 02 create_index | the same query, SCAN becomes SEARCH |
| 03 drop_index | back to SCAN, and the data is untouched |
| 04 show_indexes | `sqlite_master` and `pragma_index_list` |
| 05 unique_index | a lookup list that also forbids repeats |
| 06 clustered_index | `INTEGER PRIMARY KEY` and `WITHOUT ROWID` as the equivalents |
| 07 non_clustered_index | a two-column index and a covering index |

## SQLite notes

- There is no `CREATE CLUSTERED INDEX`. A table is stored in `rowid` order, or in primary-key order if it is `WITHOUT ROWID`.
- Plan wording can differ between SQLite versions (`SCAN pupils` or `SCAN TABLE pupils`).
